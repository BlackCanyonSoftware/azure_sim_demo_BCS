    How it works

    1. This page and its API are one small Python web app on Azure App Service (free tier). App Service's built-in sign-in sends you to Microsoft Entra ID first; only accounts on the operator list can use the API.
    2. The web app holds no keys. It signs in to Azure as its own managed identity, whose roles let it only send to the Azure Service Bus queue and read and write the results container.
    3. A worker on the home PC holds a key that can only listen. It connects out to the queue (nothing at home is open to the internet), runs the job with MuJoCo on its GPU, and uploads the results.
    4. Results go to Azure Blob Storage, which allows no public reads. The web app hands this page links that open one file for 30 minutes, signed with a key Azure lends to its identity.
    5. Application Insights traces both sides, and a budget emails before the credit runs low. The whole Azure side is one Bicep file.
